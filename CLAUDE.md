# CLAUDE.md

## What this project is

**Command** is a personal dashboard (control panel) fed by **autonomous AI agents**.
The agents explore the sources with their connectors (Gmail/Outlook, Google/Outlook Calendar,
GitHub, Trello, company planning, …) and **write the data to the server through a REST API**. The
React frontend reads the data from the server and displays it; user actions (mark as done, ack,
move card…) are saved on the server and queued so the source's agent can propagate them to the
real system.

`demo.html` is the **UX/functional reference**: design system, widgets, priority logic
("attention engine"), KPIs. It must not be modified; when implementing a widget or a domain rule,
start from there.

## Architecture

```
 AI agents (connectors)                        Browser
   │  PUT /api/ingest/:resource                  ▲  GET /api/dashboard, /api/<resource>
   │  POST/PATCH /api/agents/runs                │  PATCH /api/<resource>/:id  (user actions)
   │  POST /api/actions/claim, PATCH /:id        │  GET /api/stream  (SSE: data.changed …)
   ▼                                             │
 ┌──────────────────────── apps/server (Fastify) ────────────────────────┐
 │ routes → service → repository ── Drizzle ──► PostgreSQL                │
 │                 └─► events-bus ──► SSE                                  │
 │ `actions` table = outbox of user actions, consumed by the agents       │
 └────────────────────────────────────────────────────────────────────────┘
          ▲ types, zod schemas, domain logic: packages/shared
```

Key flows:
- **Agent ingest**: `PUT /api/ingest/:resource` with `{ runId?, mode: 'merge'|'replace', items[] }`.
  Upsert by `externalId`. `replace` deletes the records *of that agent* that are no longer present.
  Fields with user actions still `pending`/`claimed` are not overwritten by ingest.
- **User action**: `PATCH /api/<resource>/:id` updates the record immediately and creates a row in
  `actions` (`{ changes, previous }`). Undo = PATCH with the previous values.
- **Action consumption**: the agent calls `POST /api/actions/claim { resource, limit }`, applies the
  change to the real system, then `PATCH /api/actions/:id { status: 'done'|'failed', result }`.
- **Live**: every write emits an event on the events-bus, forwarded over SSE; the frontend
  refetches the indicated resource.

## API (prefix `/api`)

| Method and path | Auth | Purpose |
|---|---|---|
| `GET /dashboard` | user | snapshot + `attention`, `upcoming`, `kpis`, `projects`, `conflicts`, `sources` |
| `POST /auth/login` | — | `{ email, password }` → `TokenResponse` + refresh cookie (rate limited) |
| `POST /auth/refresh` · `POST /auth/logout` | cookie | rotates the refresh token and issues a new JWT · revokes and clears the cookie |
| `GET /auth/me` | user | current account |
| `GET /preferences` · `PATCH /preferences` | user | the user's preferences (`Preferences` in `@command/shared`: board layout, collapsed widgets, sidebar); PATCH replaces only the keys it sends |
| `GET /sources` | any | freshness per resource |
| `GET /<resource>`, `GET /<resource>/:id` | any | `emails` (`?category`), `events` (`?from&to`), `pulls`, `issues`, `reminders` (`?done`), `tasks` (`?column&board`), `projects`, `gantt` (`?assignee=me`) |
| `PATCH /<resource>/:id` | user | editable fields: see `*Patch` in `@command/shared` (`events`, `projects` are read-only) |
| `POST /reminders`, `DELETE /reminders/:id` | user | local reminders (`externalId` = `local:<uuid>`) |
| `POST /gantt/recalc` | user | reschedules by dependencies, returns `previous` for undo |
| `PUT /ingest/:resource` | agent | bulk upsert, `mode: merge\|replace`, optional `runId` |
| `POST /agents/runs`, `PATCH /agents/runs/:id` | agent | open/close a run (status, summary, error) |
| `GET /agents/me` · `GET /agents` | agent · user | agent identity · list of agents + recent runs |
| `GET /actions` · `POST /actions/claim` · `PATCH /actions/:id` | any · agent · agent | outbox: list, atomic claim (SKIP LOCKED, claims expire after 10 min), outcome |
| `GET /stream` | user (also `?access_token=`) | SSE: `ready`, `data.changed`, `agent.run`, `action.updated`, `preferences.changed` |

`GET /health` (outside the prefix) → `{ ok }`, 503 if the DB does not respond. Errors always have
the shape `ApiError { error, message, issues? }`.

## Conventions

- **A single source of truth for types**: zod schemas in `@command/shared`. Never redefine a data
  shape in the server or the web app; import it. On the wire, dates are ISO 8601 strings.
- **Layered modules**: `routes` (HTTP, validation, auth) → `service` (rules, events, outbox)
  → `repository` (Drizzle only). No queries in routes, no `request`/`reply` in services.
- **Pure domain**: functions in `shared/src/domain` take data + `now` and return values; no I/O,
  no text formatting (that belongs to the frontend). Unit tested.
- **Source records**: every resource table has `id` (uuid), `externalId` (unique),
  `agentId`, `syncedAt`, `updatedAt`. References between resources use stable keys
  (e.g. `GanttTask.projectKey` → `Project.key`, `dependsOn` → `GanttTask.key`).
- **Auth**, two distinct identities (`plugins/auth.ts`: `app.auth.user | agent | any | stream`):
  - *User*: email+password login (scrypt) → **JWT access token** HS256 (15 min, `iss=command`,
    `aud=command-dashboard`) in the body, sent as `Authorization: Bearer`; opaque **refresh token**
    (7 days) only in the `cmd_refresh` cookie, httpOnly, SameSite=Strict, path `/api/auth`, stored
    as sha256 and **rotated** on every refresh. Reusing an already rotated token (past a 30 s grace
    period) = theft → all of the user's sessions are revoked. Password change → all sessions are
    revoked. Login is rate limited, with the same response for an unknown email and a wrong password.
  - *Agent*: `cmd_agent_…` token (only its sha256 in the DB) with `scopes` over resources. A user JWT
    does not work as an agent and vice versa; read GETs accept both.
  - SSE: `EventSource` does not send headers, so `/api/stream` also accepts `?access_token=<jwt>`.
- **Frontend**: a single fetch (`GET /api/dashboard`); attention/KPIs/projects are recomputed in
  the browser with `buildInsights` from `@command/shared`, so optimistic updates and the passing of
  time show up immediately. SSE → query invalidation (300 ms debounce). Every user action goes
  through `useActions` (optimistic patch, rollback on error, Undo = PATCH with the previous values).
  Small presentational components, UI state local to the widget; UI copy in English like the demo.
- **Style**: Tailwind v4 with the demo's CSS tokens (light/dark theme via variables, no `dark:`).
  Per-element signal color with `--c`: classes `lvl-*`, `st-*`, `cat-*`, `lbl-*` + `text-c`,
  `bg-c/12`. Classes built at runtime must be added to the `@source inline(...)` safelist in
  `index.css`. Custom CSS only where Tailwind is not enough (select, switch, checkbox, Gantt clip).
- **New resource**: schema in `shared/src/schemas` + entry in `RESOURCE_SCHEMAS`, table in
  `db/schema` + `RESOURCE_TABLES`, module `modules/<r>/` (repository on `createResourceRepository`,
  service on `createResourceService`), entry in `modules/registry.ts` and `modules/resources.ts`,
  route in `API_MODULES` (`app.ts`), then `npm run db:generate`.
- The server time zone (`TZ`) defines "today"/"overdue": it must be the owner's.
- Everything in English: code, identifiers, comments and project documentation.

## Commands

Full stack in Docker (db + server + web), from a `.env` with `JWT_SECRET` set:

```bash
docker compose up -d --build         # web http://localhost:8080 · API for agents http://localhost:3000
docker compose exec server node dist/scripts/seed.js          # demo data (once)
docker compose exec server node dist/scripts/user.js <email> --name "Name"
docker compose exec server node dist/scripts/agent-token.js <name> [resources]
docker compose logs -f server
```

The server applies migrations on startup. `web` is nginx: it serves the build and proxies `/api`
(SSE without buffering), so browser and API share the same origin and the refresh cookie works.
Images in `apps/server/Dockerfile`, `apps/web/Dockerfile` (+ `nginx.conf`), build context = repo
root. For hot-reload development use `npm run dev` on the host (only `db` in Docker:
`docker compose up -d db`).

```bash
npm install
docker compose up -d db              # PostgreSQL 16 only, on localhost:5432
cp .env.example .env
npm run db:migrate                   # apply migrations
npm run db:seed                      # load the demo's mock data
npm run user:create -- <email> --name "Name"  # create the user (password prompted in the terminal)
npm run user:reset -- <email>        # new password, closes all sessions
npm run dev                          # API (:3000, watch) + web (:5173, proxies /api) together
npm run dev:api | npm run dev:web    # only one of the two
npm run agent:token -- <name> [resources,...]   # create an agent and print its token
npm run db:generate                  # after changing src/db/schema/*
npm test                             # unit (shared) + integration (server, PGlite)
npm run typecheck
```
